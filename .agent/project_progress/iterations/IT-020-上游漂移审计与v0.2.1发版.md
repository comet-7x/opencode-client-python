## 背景

v1.18.33（2026-09-28），期间 11 个 patch 未经审计：端点面、事件面（`EventType`
是开放集，服务端新增事件类型只会静默以基类流过）、模型 schema 均可能漂移。

端口统一 4096），CHANGELOG 无 [Unreleased] 段落，对使用者不可见。

目标：① 审计漂移并按需修复；② 给出"客户端支持/已验证的 server 版本"明确
口径；③ 收敛积压工作发版。

## 审计记录

**OpenAPI 面 diff**（1.18.21 导出 vs 1.18.33 导出，脚本比对 188 操作/472
schema/94 Event* schema）：

- 操作：188 → 188，**零增删**；路径项（非方法部分）零变化
- schema：472 → 472，名称零增删；Event* 94 → 94 零增删（事件面稳定）
- 内容差异仅 2 处：
  1. `ProviderConfig`：字段重排 + `chunkTimeout`/`headerTimeout` 描述措辞
     微调（chunkTimeout 明确为 SSE 分块间超时，默认 300000ms）——无增删
     字段、无类型变化，客户端未建模该 schema，零影响
  2. `POST /global/upgrade`：请求体 `target` 从可选变**必填**（描述同步
     从"or latest if not specified"改为"to the specified version"）

**行为验证**（对真实 1.18.33 容器，4096）：

- live 套件 11 用例全过（修复环境问题后，见决策记录 2）
- `upgrade_global` 探针：无请求体 → 400 "Expected object, got undefined"；
  `{}` → 400 "Missing key at [target]"——坐实必填；1.18.21 的 OpenAPI 描述
  佐证旧版接受省略
- 端点级 A/B（1.18.21 vs 1.18.33 容器互换）：`/file`、`/file/content`、
  `/file/status`、`/find`、`/find/file` 行为一致；**不可见目录（宿主机
  pytest tmp）两代服务端同样 500 UnknownError**——live files 用例此前
  通过依赖的是 Docker Desktop 当时共享了 `/private`，属本机环境漂移，
  非上游漂移
- 附带发现：未知路径（如误写的 `/file/list`、`/find/text`，历史上从不存在）
  落 web UI 兜底页返回 200 HTML——调试时注意看 content-type

## 决策记录

1. **`upgrade_global(target)` 改必填**，而非客户端默认补 `"latest"`：旧
   服务端会把显式值当版本名处理，`"latest"` 能否解析无法安全验证（真发
   请求会触发自升级）；必填参数对两代服务端都正确。**版本号 v0.2.1**
   （用户拍板：变更面小不跳 minor，接受 patch 内含这一处签名收紧；
   pre-1.0 无兼容承诺）。四类（sync/async/raw×2）逐字对齐，镜像一致性锁把关。
2. **live files 用例改为仓库根 scratch**：pytest tmp 目录容器不可见是
   环境问题而非漂移，但既然暴露就修掉——scratch 写在仓库根
   `.tmp-live/`（compose 标准挂载进容器 `/app`），`directory` 传服务端
   视图（默认 `/app`，宿主机原生 serve 用 `OPENCODE_LIVE_WORKDIR` 覆盖），
   测试不再依赖 Docker Desktop 文件共享配置。
3. **OpenAPI 权威源升级为 1.18.33 导出**（162 paths 不变），旧导出存档为
   同目录 `opencode_rest_api_1.18.21.json` 作审计基线；AGENTS.md 指针
   描述（162 paths）仍准确，无需改。
4. **Docker 镜像 pin 保持 1.18.21**：pin 语义 = 支持下限 + 本地开发标准；
   兼容口径由 README 承载（1.18.21+，已验证至 1.18.33）。
