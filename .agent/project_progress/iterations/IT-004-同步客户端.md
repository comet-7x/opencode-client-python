# IT-004 同步客户端 + 官方 SDK 优势吸收

- 状态：✅ 完成（2026-08-22）
- 所属里程碑：M3 功能扩张（工程化：sync/async 对等）

## 目标

补齐 sync 客户端（此前仅 async），并对照官方 SDK（Stainless 生成）取长补短：
吸收 sync/async 对等、分层异常、`NOT_GIVEN` 哨兵、自动重试、`with_options` 等优势，
保持轻量手写（不照搬 8000 行生成代码）。

## 任务

### 选型对比（官方 vs 我们）
- [x] 调研官方双客户端模式：`Opencode`(sync)/`AsyncOpencode`(async)，每域 Sync/Async 双类
- [x] 定方案：**不按域双类**，改为「每资源类持 sync+async 客户端，wire/parse 抽纯函数共享」，DRY 且轻量
- [x] 命名（用户拍板）：`OpenCodeClient`=sync、`AsyncOpenCodeClient`=async（对齐官方，0.1.0 未发布故接受破坏性变更）

### 双客户端
- [x] `client.py`：`ClientOptions` + `OpenCodeClient`/`AsyncOpenCodeClient`，方法签名对等
- [x] 共享 wire 层 `resources/_wire.py`：`request_spec`/`prompt_body`/`validate_response`(泛型) + 各 body/query 纯函数
- [x] `resources/base.py`：`Resource`(sync)/`AsyncResource`(async) 组合基类
- [x] `resources/sessions.py`、`resources/server.py`：sync/async 双资源，仅差 `await`
- [x] `sse.py`：新增 `SyncEventStream`，与 async `EventStream` 对等

### 吸收官方优势
- [x] 分层异常 `errors.py`：`OpenCodeError` ← `OpenCodeApiError` ← (NotFound/Auth/Permission/Conflict/Unprocessable/RateLimit/Server)；
      传输层 `OpenCodeTransportError` ← (Timeout/ServerConnection)；`make_api_error`/`make_transport_error` 映射
- [x] `NOT_GIVEN` 哨兵 `_types.py`：`with_options` 精确 override（区分"没传"与"传 None"）
- [x] 自动重试：429/5xx/连接错误触发，指数退避（0.5s 起，封顶 8s）+ 尊重 `Retry-After`
- [x] `with_options(base_url/timeout/max_retries)` 派生客户端

### 测试
- [x] `tests/test_client.py`：对齐 `AsyncOpenCodeClient`（旧 async 命名）
- [x] `tests/test_sync_client.py`（新增 11 项）：sync 全套 + 重试 5 项（成功/4xx 不重试/耗尽/连接/超时）+ `with_options` 2 项
- [x] 分层异常映射验证（404 → `OpenCodeNotFoundError`）

### 验证
- [x] 全门禁：ruff / format / mypy(src+tests 21 文件) / pyright strict / pytest 34 passed
- [x] 真实服务双端冒烟（opencode v1.18.18 @ 127.0.0.1:20001，provider `steins-middleware-vllm`/`Qwen/Qwen3.8-27B`）：
      sync + async 各自 health/agents/create/prompt("pong", finish=stop)/history/fork/abort/delete 全通过；
      404 正确抛 `OpenCodeNotFoundError`
